# 상담자 역할 게임 자기적용 연구 시스템 (간편판)

참가자가 상담자가 되어 캐릭터(민서·지호·서윤)의 고민을 듣고 조언을 건넨 뒤, AI가 그 조언을 **나에게 하는 말**로 바꿔 돌려주면 자기 경험에 비추어 보는 연구용 웹 시스템입니다.
연구자는 **웹 대시보드**에서 결과와 통계를 바로 확인합니다.

## 흐름

참가자 화면 위에는 3구간만 보입니다: **1. 캐릭터 돕기 → 2. 내 이야기 → 3. 돌아보기** (세부 단계 번호는 숨김). S1 안내도 이 3구간으로만 설명하고, "내가 한 조언이 나에게 돌아온다"는 것은 미리 알리지 않습니다.

| 구간 | 단계 | 화면 제목 | 내용 |
|---|---|---|---|
| | S1 | 상담 연습에 오신 것을 환영해요 | 3구간 안내, 참가자 ID(선택), 동의 체크 |
| 1 | S2 | 도와줄 사람 고르기 | 세 사람 중 비슷한 경험이 있는 사람 선택 (셋 다 없으면 종료) |
| 1 | S3 | ○○의 이야기 듣기 | 캐릭터의 직전 대사에 이어지는 말 3개 중 하나 고르기 × 3턴. 세 선택지는 상담자 태도(공감·구체화·탐색)만 다름 |
| 1 | S4 | ○○에게 조언 건네기 | 정해진 횟수(기본 3회) 조언. 회차 사이 캐릭터는 고정 후속 고민, 마지막은 중립 마무리. **세 조언을 합쳐 한 번만 AI 변환** (조언으로 안 읽히면 한 번 더 쓰기) |
| 2 | S5 | 내 경험 떠올리기 | 경험·감정·그때 든 생각, 믿음 정도(0~100), 지금의 해석 |
| 3 | S6 | 나에게 돌아온 말 | 변환문이 뜻을 담았는지, 고쳐 쓰기 (변환 ok일 때만) |
| 3 | S7 | 사실 모아보기 | 그 생각을 지지하는 사실 / 반박하는 사실 |
| 3 | S8 | 조언이 나에게도 맞을까? | 공통점·차이점, 수용·수정·보류·거부와 이유 (변환 ok일 때만) |
| 3 | S9 | 다시 돌아보기 | 믿음 정도·해석 다시 답하기 (S5와 같은 문구) |
| 3 | S10 | 마지막 질문 | 1~5점 (ok 경로 11문항, 그 외 5문항) |
| | S11 | 끝났어요 | |

- 입력 화면마다 **할 일 한 줄 + 칸별 안내 질문 + 예시(placeholder)** 가 있고, 아래에 "정답은 없어요. 떠오르는 대로 적어도 괜찮아요."가 붙습니다. 예시는 캐릭터 고민과 겹치지 않게 운동(달리기) 이야기로 썼습니다.
- 캐릭터 대사마다 표정(기본·불안·슬픔·망설임·조금 누그러짐)이 붙습니다. 조언 뒤 반응은 '조금 누그러짐'까지만 씁니다(웃는 표정 없음 — "좋은 조언 = 정답" 신호 방지).

AI로 보내는 것은 **S4 조언(합친 것) + 캐릭터 상황 설명**뿐입니다. S5 이후 기록은 보내지 않습니다. 위험 신호 검사는 조언 회차마다 제출할 때 합니다.

## 노트북에서 실행

1. Node.js 20.12 이상 설치 (https://nodejs.org)
2. 이 폴더에서 처음 한 번:
   ```
   npm install
   ```
3. `.env.example`을 복사해 `.env`를 만들고 `GEMINI_API_KEY`를 넣습니다. 키를 비워 두면 **모의(mock) 모드**(가짜 변환 문장)로 동작합니다.
4. 서버 켜기:
   ```
   npm start
   ```
   창에 주소가 나옵니다.
   - 참가자 화면: `http://localhost:3000`
   - 연구자 대시보드: `http://localhost:3000/admin`
   - 같은 와이파이의 다른 기기: 창에 나온 `http://192.168.x.x:3000`

자체 테스트 데이터를 따로 두려면 `.env`에 `DATA_DIR=data-selftest`를 넣고 켭니다. 본 실험 때 `DATA_DIR=data`로 바꾸면 대시보드도 그 폴더만 봅니다.

## 다른 사람에게 링크로 받기 (인터넷)

1. cloudflared 설치 (한 번만)
   - 윈도우: `winget install --id Cloudflare.cloudflared`
   - 맥: `brew install cloudflared`
2. `.env`에 `ACCESS_CODE=아무코드`를 넣고 서버를 켭니다(`npm start`).
3. 새 창에서 `npm run tunnel` → 화면에 나온 **참가자 링크**를 보냅니다. 예: `https://xxxx.trycloudflare.com/?pid=P01&code=아무코드`

- 노트북과 두 창을 켜 둬야 링크가 살아 있습니다. 터널을 다시 켜면 주소가 바뀝니다.
- 외부에서 들어온 요청은 주소당 1시간에 세션 60개까지 만들 수 있습니다(API 요금 보호).

## 연구자 대시보드 (`/admin`)

필터(맨 위): AI 모드(실제/모의) · 단계(본실험/파일럿) · 캐릭터. 모든 탭과 내보내기에 그대로 적용됩니다.
**분석 가능 = 완료 & 기준 D 제외 아님.** 새 세션은 `.env`의 `STUDY_PHASE`(기본 pilot)로 표시되고, 세션 기록에서 바꿀 수 있습니다. 파일럿 자료는 본 분석에 넣지 않습니다(필터 '본실험').

- **통계 탭** (15초마다 새로고침)
  - 시작·완료·중도 종료, 단계별 도달·소요 시간, 캐릭터 선택·관련성
  - **대화 선택 분포**: 턴별 선택지(공감·구체화·탐색) 비율. 한 선택지에 80% 이상 몰리면 ⚠ — 파일럿 후 선택지를 다시 쓰세요(선택지마다 노출 사실이 달라 조언 질 분석이 치우침)
  - 조언 변환 결과(ok·조언 아님·unsafe·blaming·safety_hold·fallback)와 조언 유형
  - 믿음 정도 사전→사후: 참가자별 선 그래프, 참고용 검정(대응 t·95% CI·dz·윌콕슨)
  - S6 뜻 보존·S8 판단 분포와 교차표, 설문 중앙값[사분위 범위](역문항 q7·q11 표시)
  - **RQ2 보조 분석**: "잘 담겼다"인데 수정·보류·거부한 사례, q9×q2(충실↑·적용↓ 사례), q10×q11, 인터뷰 주제별 인원
  - **제외·종료 보고**: 완료·분석 가능·기준 D 제외(그중 not_advice)·경험 없음·그만두기(단계별)·진행 중
- **RQ1 코딩 탭** (명세 §7 기준 A·B·C, 기준 원문이 화면에 표시됨)
  - 시트: A 재검토(S5·S9 해석) · B 자기적용(S5·S9 해석, ok만) · B 자기적용(S8 응답, ok만) · C 조언 질
  - 글은 무작위 ID로 섞여 나오고 참가자·시점은 숨겨집니다. B는 시점별 원칙 기준(S5는 조언만, S8·S9는 그때까지 본 문장)을 함께 보여 줍니다.
  - 코더 1·2가 점수를 누르면 바로 저장 → '합의'에서 다르게 본 항목의 최종 점수를 정합니다.
  - 결과: S9 재검토·S8/S9 자기적용 수준 분포(주 분석), S5→S9 방향(보조), 조언 질 × S8 자기적용, 과정 지표 × S9 재검토 수준, 참가자별 점수, 시트별 일치도(일치율·이차 가중 κ)
- **RQ3 코딩 탭**: 완료 & 변환 ok 참가자마다 AI 변환문과 규칙 변환문(`content/rulebased/rules.json`)을 출처를 숨겨 섞고 상황절은 [상황]으로 가립니다.
  - 코더 1·2가 정상 / 오류 유형 8가지 / 틀 차이를 체크 → '합의'로 최종 판정
  - 결과: 방식별 오류율·유형·심각도, 일치도(일치율·κ·PABAK·AC1), S4 입력 차수 기준 ok 성공률과 실패 경로, S6 참가자 판단 × 코더 판정
- **세션 기록 탭**: 참가자별 글 전체, AI 호출 원문(JSON), 이벤트 타임라인 내려받기, 세션 삭제
  - **분석 관리**: 단계(본실험/파일럿), 기준 D 제외와 사유
  - **인터뷰**(완료자): 명세 §13.5 질문을 경로(ok/예외)별로 보여 주고, 질문별 요약·인용·무응답 코드·추가 질문·녹음 동의·안전 사건·주제를 기록합니다. 주제는 RQ2 집계에 쓰입니다.
- **내보내기 탭**: 세션 CSV(한 사람당 한 행: 단계별 시간 `sec_*`, 글자 수 `len_*`, 노출 사실 `fact_ids`, 단계·제외 포함), RQ1 코딩 CSV, RQ3 코딩 CSV(출처 공개 — 코더에게 보여 주지 마세요), AI 호출 기록(llm_log), 전체 JSON, 통계 보고서 HTML(통계·RQ1·RQ3 결과, PDF로 인쇄 가능)
- 접근: `.env`에 `ADMIN_TOKEN`이 없으면 **서버를 켠 PC에서만** 열립니다. 다른 PC에서 보려면 `ADMIN_TOKEN`을 정하고 그 비밀번호를 입력합니다.

통계 계산은 scipy 1.18(대응 t·윌콕슨)·scikit-learn(가중 κ·κ) 결과와 대조해 확인했습니다(`tests/stats.test.js`, `tests/research.test.js`). 명세 §8은 기술통계·개인별 변화·사례 중심이므로 p값은 참고로만 쓰세요.

## 내용 고치기

| 무엇 | 파일 |
|---|---|
| 캐릭터·대사·표정·후속 고민 | `content/scenarios/<id>/scenario.json` (순서·조언 횟수 `adviceRounds`는 `content/study.json`) |
| 표정 이미지 | `content/scenarios/<id>/faces/<표정>.svg` — 지금은 `node scripts/make-faces.js`로 만든 단순 도형 초안. 직접 만든 그림으로 같은 이름의 SVG를 바꿔 넣으면 됩니다(기존 캐릭터를 닮은 그림 금지) |
| 화면 문구·설문 문항 | `content/ui/strings.json` |
| 변환 프롬프트 | `content/prompts/transform/v3.md` (여러 회차 조언을 합쳐 판정. 새 버전은 `v4.md`로 만들고 `.env`의 `TRANSFORM_PROMPT=v4`) |
| 위험 키워드 | `content/safety/rules.json` |
| RQ1 코딩 기준(A~D) | `content/coding/criteria.json` |
| 인터뷰 질문 | `content/interview/protocol.json` |
| RQ3 규칙 변환 치환표 | `content/rulebased/rules.json` (바꾸면 `version`을 올리세요. 이미 만든 코딩 문장은 그대로 유지됩니다) |

문구 파일은 서버 재시작 없이 다음 화면부터 반영됩니다. 세션 기록에는 콘텐츠 해시와 프롬프트 해시가 남아 어떤 버전으로 얻은 결과인지 구분됩니다.

**위험 키워드**는 두 종류입니다.
- 위험 신호(urgent): 화면에 상담전화 안내(109, 1577-0199)를 띄우고 기록합니다. 진행은 계속됩니다.
- 조언 속 위험·비난(unsafe·blaming): AI 호출 없이 해당 결과로 분류합니다.

**파일럿에서 확인할 것**
- 대화 선택 분포 ⚠ 여부
- 세션 시간: 완료자 소요 시간 중앙값이 35분을 넘으면 `content/study.json`의 `adviceRounds`를 2로 줄입니다(회차는 모든 참가자 동일해야 하므로 실험 도중에는 바꾸지 마세요).

## 사전 점검 (명세 §5·§10.10)

```
npm run check:transform                                  # 현재 프롬프트, 항목당 3회
npm run check:transform -- --prompt v3 --compare v2      # 두 버전 비교
```
`content/prompts/transform/tests.json`(29항목)을 3회씩 변환해 `results/`에 항목별 CSV와 지표 요약 CSV를 만듭니다.
- (a) raw try 분모: 형식 오류, 시간 초과·오류, 안전 긍정 탐지
- (b) trial 최종 결과 분모: 기대 outcome 일치율 → **90% 게이트**
- (c) 3회 모두 기대값과 일치한 항목 비율, 매번 같은 결과가 나온 항목 수
- 안전 false negative 0건, ok 출력 형식 유효 100% 게이트. 심각 의미 반전·위험 출력 노출은 CSV의 `human_*` 열에 직접 판정합니다.

모의 모드에서 화면 경로를 시험하려면 조언 끝에 `#notadvice #unsafe #blaming #badjson #latchbad #error`를 붙입니다(모의 모드의 사전 점검 수치는 의미가 없습니다).
