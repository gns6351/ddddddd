# 진행 기록

## 지금 상태 (기준 v5)

사람 참가자 없이 하는 기술 평가 시스템. 참가자 화면은 시연용으로 남아 있다.

- **RQ1** 자기지향 변환의 의미 보존과 판단 여지를 줄이는 변형.
- **RQ2** 판정·점검 파이프라인이 부적절한 입력과 심각한 오류를 걸러내는 정도, 걸러내지 못하거나 통과시킨 변형 유형.
- **주요 파일**
  - `server/pipeline.js`: 규칙 → 판정·변환 → 형식·의미 점검(반전·추가·forcing) → 다시 변환.
  - `server/lab.js`: 샘플·페르소나 생성·오류 주입·실행. 실행 범위는 파일럿 / 본 실행 / 주입 문장만 점검.
  - `server/results.js`: RQ1·RQ2 계산, Wilson 구간.
  - `server/coding.js`: 정답 라벨, 변환 오류, 주입 문장 코딩.
  - `public/admin.*`: 대시보드.
- **기준과 프롬프트**
  - `content/coding/criteria.json` v5. 코더용 설명은 `docs/codebook.md`.
  - 변환 프롬프트 `transform/v5`, 점검 프롬프트 `check/v2`(forcing 포함).
- **미검증:** 실제 Gemini 호출. 이 환경에 키가 없어 생성·변환·점검·주입 모두 가짜 클라이언트와 모의 응답으로만 확인했다.
- **남은 일(연구진)**
  - 파일럿 샘플과 본 샘플(약 45개)을 작성한다.
  - 페르소나·코드북 예시를 검토한다.
  - 파일럿 실행으로 프롬프트와 형식 점검 길이 기준을 고정한다.
  - 변환·점검·생성 모델을 서로 다르게 정한다.
  - 코더 2명이 연습한 뒤 기준을 고정한다.
  - 소속 기관 IRB에 심의 대상이 아닌지 확인한다.

## 기준 v5 반영 (연구자 정리안 B1~B5)

**B1. 기준·프롬프트·규칙**
- `criteria.json` v5
  - 오류 코드 추가: 새 당위, 선택·유보 삭제, 결심·동의 생성. 셋 다 심각 오류이면서 판단 여지 축소에 해당한다.
  - 정의 수정: 정도 강화는 "정도만" 바뀐 경우, 의미 추가에는 위로·평가를 포함한다.
  - 주입 유형 6개: 막아야 하는 것은 반전·추가·새 당위·선택·유보 삭제, 통과해야 하는 것은 정도 강화·표현만 바꿈. 약한 일반화는 코딩용 오류 코드로만 남겼다.
  - 정책 문구를 넣었다.
- 프롬프트
  - 점검 v2: forcing 판정을 추가했다. 스키마는 `schema-v2.json`으로 따로 두어 v1도 그대로 쓸 수 있다.
  - 변환 v5: 조건·선택지를 빼지 않고, 결심을 만들지 않는다는 지시를 넣었다.
  - 오류 주입: 조건이 없는 문장이면 빈 출력을 내고, 그 경우 건너뛴다.
- 안전 규칙 오탐 수정: b01(앞에 한글이 오면 제외, "네 탓이라고 생각하지 마"·"하지 마"는 제외), b03(2인칭이 대상일 때만), r04(권유형만 잡음).

**B2. 서버**
- 2인칭 소유격을 잡고 수량 표현은 제외한다.
- 점검에 forcing을 반영했다. forcing이 boolean인지 검사하고, v1 응답처럼 forcing이 없으면 false로 본다.
- 시간 제한을 호출마다 AbortController로 걸어 요청을 실제로 취소한다. 클라이언트에 고정한 timeout은 없앴다.
- 기본 프롬프트를 v5·v2로 바꿨다.
- 결과 계산(`results.js`)
  - 확정은 두 코더 일치 또는 합의만으로 한다.
  - RQ1 대상은 정답이 조언인 샘플로 좁히고, 변환문이 없는 건수는 따로 센다.
  - AI 오류·지연은 막음으로 세지 않고 따로 세며, 분모에서도 뺀다.
  - 주입 문장의 정답은 코더 판정을 우선하고, 없으면 주입 유형으로 대신한다.
  - 그대로 돌아간 변환문을 놓침과 의도적 통과로 나눴다.
  - 비율에 Wilson 구간을 붙였다(`stats.wilson`, scipy와 대조함).
  - CSV에 `check_forcing` 열을 넣었다.
- 샘플을 파일럿과 본 실행으로 나누고, 실행 범위(파일럿 / 본 실행 / 주입만)를 고를 수 있게 했다. 주입만 한 실행은 결과 탭에서 앞선 본 실행에 붙여 보여 준다.
- 주입 기준 문장을 직접 고를 수 있다.

**B3. 대시보드**
- 정책과 주입 유형 문구를 기준 파일에서 읽는다.
- 비율 옆에 [95% 구간]을 표시한다.
- 판정 대기, 변환문 없음, AI 오류 건수를 보여 준다.
- 놓침과 의도적 통과를 나눠 보여 준다.
- 샘플 표에 구분(본 실행 / 파일럿) 열을 넣었다.
- 주입 기준 문장 선택 표, 실행 범위 선택을 넣었다.

**B4. 테스트 결과(실행함):** `npm test` 30/30, `npm run test:e2e` 3/3 통과. 새로 넣은 테스트는 다음과 같다.
- 안전 규칙 오탐 사례
- 2인칭 소유격과 수량 표현
- forcing으로 점검 실패한 뒤 다시 변환
- Wilson 구간 값
- AI 오류·지연을 따로 집계
- 코더 1명 판정은 확정이 아님
- 파일럿 분리
- 주입 6유형과 건너뜀, 주입만 실행, 코더 판정을 정답으로 사용
- 코딩 시트 기본 실행
- Host 검사

**B5. 기타:** 비밀번호가 없을 때는 Host가 localhost·127.0.0.1인 요청만 연구자 화면을 연다.

## 거울상담소 게임 서버 — 요구사항의 AI 부분 (중간보고서 FR-01~12 · NFR-01~08)
- 게임 API `/api/game`(`server/game/`), 게임 콘텐츠 `content/game/`, 게임 프롬프트 `content/prompts/game/`(guest·turn·judge·mirror·check·risk·player v1). 논문용 API·프롬프트와 분리(NFR-08). 앱 연동 문서 `docs/game-api.md`.
- 구현: 위험 발화(규칙 → AI, 걱정·매 턴, 도움 안내 후 재개 없음), 손님 생성(1회 재시도 → 예시 손님, 다시 만들기 1회), 손님 턴(대사+선택지 한 번의 호출, 사실·정정 누적), 서버 턴 규칙(3·6·8턴 조언 요청, 6턴+하이라이트 시 마무리 제안, 12턴 자동 종료), 조언 하이라이트(직접 입력 턴만, 원문 그대로), 거울 장면(앞뒤 발화 포함 변환 → 형식·의미 점검 → 1회 재변환 → 원문만), 비교·판단(AI 초안·수정본 분리), requestId 중복 방지·세션별 직렬 처리·실패 시 상태 복원, 동의·미저장·카드·삭제, 판당 호출 상한(거울용 4회 남김)·원문 없는 호출 로그.
- 테스트 도구: `npm run game:sim`(페르소나 10종, 완주율·턴·서술형 입력·위험 감지·응답 시간 p95·판당 호출, 제작자 판정용 guests.csv), `npm run game:risk`(위험 40 + 대조 20, 두 경로), `npm run game:report`(로그 집계).
- 테스트(실행함): `npm test` 49/49(게임 18개 포함), `npm run test:e2e` 3/3. 모의 모드로 `game:sim`(12판)·`game:risk`·`game:report` 실행 확인.
- 미검증: 실제 Gemini 호출(키 없음). 특히 간접 위험 표현 20개 감지(NFR-05), 응답 시간 p95(NFR-01), 완주율 90%(NFR-06)는 실제 모델로 `game:risk`·`game:sim`을 돌려야 확인됨. Android 앱 화면은 미착수.
