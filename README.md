# 자기 조언 되돌려 받기 연구 시스템 (명세 v4.2 간소화판)

참가자가 학업 실패감을 가진 캐릭터 한 명에게 **조언 하나**를 건네면, AI가 그 조언을 **나에게 하는 말**로 바꿔 돌려줍니다. 참가자는 그 말이 내 뜻을 담았는지, 지금의 나에게 쓸지를 판단합니다.
연구자는 **웹 대시보드**에서 결과와 통계를 바로 확인하고, 코딩도 웹에서 합니다.

- **RQ1 변환 품질**: LLM은 조언을 자기에게 하는 말로 바꿀 때 의미를 얼마나 보존하는가? (주 자료: 실험 전 샘플 검증)
- **RQ2 자기적용 과정**: 돌려받은 자기 조언을 어떻게 적용하며, 그대로·고쳐서·미루기·안 맞음을 고르는 이유는 무엇인가? (효과 판정 없이 기술)

## 흐름

참가자 화면 위에는 3구간만 보입니다: **1. 캐릭터 돕기 → 2. 내 이야기 → 3. 마무리**. 조언이 돌아온다는 사실은 미리 알리지 않습니다(거리두기 조건). 모든 단계는 앞으로만 진행됩니다.

| 단계 | 화면 | 입력 |
|---|---|---|
| S1 시작 | 안내·동의 + 사전 선별("뭘 해도 안 될 것 같다"는 생각을 해 본 적? 없으면 종료) + 관련성 1~5 | 탭 |
| S2 고정 대화 | 캐릭터 첫 대사 → 선택지 3개(공감·구체화·탐색) 중 1개 → 고정 답 + 질문 | 탭 1회 |
| S3 조언 | 조언 1개. "조언 아님"이면 캐릭터가 한 번 더 물음(재질문 1회) | 자유 입력 |
| S4 내 경험 | 그때 든 생각 한 줄 (비슷했던 상황은 선택) — **AI로 보내지 않음** | 한 줄 |
| S5 돌아온 말 | 원문과 변환문을 나란히. 잘 담김 / 조금 다름 / 많이 다름. '고치기'를 눌러야 입력창이 열림 | 탭, 고치기 선택 |
| S6 나에게 할 말 | 위에 그때 든 생각, 아래에 변환문(S5에서 고쳤으면 고친 문장). 그대로 / 고쳐서 / 미루기 / 안 맞음 | 탭, 고쳐서면 수정 |
| S7 이유 | S6 판단별 이유 선택지 하나 (+ 일부 선택지는 한 줄). 분석 범주는 화면에 안 보임 | 탭 |
| S8 설문 | q10(주도권), q11(역문항) — 디브리핑 **전에** 받음 | 탭 2회 |
| S9 마무리 | 디브리핑(조언이 돌아온 이유, 실패 경로면 돌아오지 않은 이유) → 데이터 철회 선택 | 탭 |
| 끝 | 감사 + 상담 자원 안내(교내 상담센터·109·1577-0199) | |

- **실패 경로**: 조언 아님(재질문 후 또 조언 아님)·비난·위험·AI 오류/지연·변환 점검 두 번 실패 → S4~S8을 건너뛰고 S9로.
- **그만하기**: 어느 단계에서든 S9 마무리(디브리핑·철회 선택)로 갑니다.
- 캐릭터 표정은 기본·속상함 두 가지뿐(웃는 표정 없음).

## AI 처리 (조언 판정 → 자기지향 변환 → 변환 점검)

1. **규칙 사전 검사** (`content/safety/rules.json`): 명백한 위험·비난 표현은 AI로 보내지 않고 바로 실패 경로.
2. **판정 + 변환** (Gemini, 프롬프트 `content/prompts/transform/v4.md`): `{verdict: ok|not_advice|blame|risk, self}` JSON 하나.
3. **변환 점검**: 심각한 오류만 거르고 미세한 변화(강도·약한 일반화·어휘)는 통과시킵니다(RQ1 분석 대상).
   - 형식(규칙): 2인칭(너·네가·당신…)이 남음, 빈 출력, 지나친 길이 증가(기준은 `content/study.json`의 `check`, 짧은 조언은 예외)
   - 의미(AI, `content/prompts/check/v1.md`): 뜻 반전, 원문에 없는 조언·사실 추가 (상황절은 추가로 보지 않음)
   - 실패하면 **다시 변환 1회**, 또 실패하면 실패 경로. 점검 모델은 `.env`의 `CHECK_MODEL` — 변환과 **다른 모델 권장**.
4. AI로 보내는 것은 **S3 조언 원문과 그 변환문뿐**. S4~S7 입력은 보내지 않습니다(테스트로 확인).

## 노트북에서 실행

1. Node.js 20.12 이상 설치 (https://nodejs.org)
2. 이 폴더에서 처음 한 번: `npm install`
3. `.env.example`을 복사해 `.env`를 만들고 `GEMINI_API_KEY`를 넣습니다. 키를 비워 두면 **모의(mock) 모드**(가짜 변환 문장)로 동작합니다.
4. `npm start` → 창에 주소가 나옵니다.
   - 참가자 화면: `http://localhost:3000` (`?pid=P01`을 붙이면 참가자 ID가 채워짐)
   - 연구자 대시보드: `http://localhost:3000/admin`

자체 테스트 데이터를 따로 두려면 `.env`에 `DATA_DIR=data-selftest`를 넣고 켭니다.

## 다른 사람에게 링크로 받기 (인터넷)

1. cloudflared 설치 (한 번만) — 윈도우: `winget install --id Cloudflare.cloudflared` / 맥: `brew install cloudflared`
2. `.env`에 `ACCESS_CODE=아무코드`를 넣고 서버를 켭니다(`npm start`).
3. 새 창에서 `npm run tunnel` → 화면에 나온 **참가자 링크**를 보냅니다. 예: `https://xxxx.trycloudflare.com/?pid=P01&code=아무코드`

## 연구자 대시보드 (`/admin`)

필터: AI 모드(실제/모의) · 단계(본실험/파일럿). 새 세션은 `.env`의 `STUDY_PHASE`(기본 pilot)로 표시되고 세션 탭에서 바꿀 수 있습니다.
**분석 대상** = 분석 제외(무의미 입력, 연구자 2인 합의)·데이터 철회·사전 선별 탈락이 아닌 세션. 사용자 자료의 분모는 **ok 경로**이고, 제출 대비 ok·실패 비율과 실패 사유를 함께 냅니다. 사용자 자료는 **n/N**으로만 보이고 퍼센트·검정은 쓰지 않습니다.

- **한눈에 보기**: 시작·선별 탈락·완료·그만둠·철회·제외, ok 경로 인원(목표 10명), S4 기록 확인 대기, 단계별 도달·소요 시간, 조언 제출 대비 경로·실패 사유, 재질문 사용, 관련성 분포
- **RQ1 변환 품질**
  - 실험 전 검증(주 자료): '샘플 검증 실행' → 실행(프롬프트 버전)별 판정 분포, 첫 변환 점검 결과, 코더 판정 오류 유형, 출처별 오류율, **자동 점검 성능**(심각한 오류를 잡음/놓침, 미세한 변화를 통과/지나치게 막음)
  - 실험 중 점검: 형식·의미 실패 건수와 유형, 다시 변환 성공 건수
  - 참가자 변환문: 코더 판정 오류 유형, 보조로 사용자 S5 판단 × 코더 판정
  - 코더 일치도: 유형별 일치율·κ, 불일치 건수
- **RQ2 자기적용**: S6 판단 분포, S5 충실도 × S6 판단(상황 탓 / 번역 탓), S7 이유와 분석 범주(1차 분류 vs 코더 확정), **사례**(잘 담김 → 미루기·안 맞음), 고쳐 쓴 문장 변화 유형, q10·q11 중앙값[IQR](합산 없음, q11 역문항)
- **코딩**: 시트 4개 — 실험 전 검증 / 참가자 변환문(오류 유형 6가지, `content/coding/criteria.json`), S7 이유 범주 확정, 고쳐 쓴 문장 변화 유형(새 유형 자유 입력). 코더 1·2가 독립 판정 → '합의'에서 다르게 본 것만 정함. 항목은 무작위 ID, 참가자·사용자 판단·자동 점검 결과는 숨김.
- **세션**: 참가자별 전체 기록과 AI 호출 원문, 단계(파일럿/본실험), **S4 기록 확인함**(세션 중 위기 신호 자동 감지를 하지 않으므로 세션 후 확인), 분석 제외와 사유, 삭제
- **내보내기**: 세션 CSV(명세 기록 필드, 한 사람당 한 행, 단계별 진입·완료 시각), 실험 전 검증 CSV, 코딩 결과 CSV, AI 호출 기록, 전체 JSON, 통계 보고서 HTML

접근: `.env`에 `ADMIN_TOKEN`이 없으면 서버를 켠 PC에서만 열립니다.

## 실험 전 검증

1. `content/validation/samples.json`에 샘플 조언 30~50개를 넣습니다(지금은 동작 확인용 예시 8개). `source`(researcher / public / persona 등)로 출처별 오류율을 따로 봅니다.
2. 대시보드 'RQ1 변환 품질' → '샘플 검증 실행' (또는 터미널에서 `npm run validate -- --note "v4 첫 검증"`). 결과는 `data/validation/<실행ID>.json`.
3. 코딩 탭 '실험 전 검증'에서 두 코더가 판정 → 합의.
4. 뜻 반전·내용 추가가 통과 기준 이하가 될 때까지 프롬프트를 고칩니다(새 버전 `v5.md` → `.env` `TRANSFORM_PROMPT=v5` → 다시 실행). 실행마다 프롬프트 해시가 남아 버전별로 비교됩니다.

모의 모드에서 경로를 시험하려면 조언에 태그를 붙입니다: `#notadvice #blame #risk #badjson #error #slow`(변환), `#reversal #addition`(점검 실패), `#reversal1`(첫 점검만 실패 → 다시 변환 성공), `#you`(2인칭 남음 → 형식 실패).

## 내용 고치기

| 무엇 | 파일 |
|---|---|
| 캐릭터 이름·대사·선택지·재질문·마무리 | `content/character/character.json` (초안, 이름은 임시) |
| 표정 이미지 | `content/character/faces/{neutral,sad}.svg` — `npm run faces`로 만든 단순 도형 초안. 같은 이름의 SVG로 바꿔 넣으면 됨 |
| 화면 문구·디브리핑·상담 자원·설문 | `content/ui/strings.json` (교내 상담센터 연락처는 배포 전에 입력) |
| S7 이유 선택지와 분석 범주, 형식 점검 기준 | `content/study.json` |
| 변환·점검 프롬프트 | `content/prompts/transform/v4.md`, `content/prompts/check/v1.md` |
| 규칙 사전 검사 | `content/safety/rules.json` |
| 코딩 기준(오류 유형·변화 유형) | `content/coding/criteria.json` |
| 실험 전 검증 샘플 | `content/validation/samples.json` |

문구 파일은 서버 재시작 없이 다음 화면부터 반영됩니다. 세션에는 콘텐츠 해시와 프롬프트 해시가 남습니다.
