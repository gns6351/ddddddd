# 자기 조언 되돌려 받기: LLM 거울의 설계와 기술 평가

남에게 한 조언을 AI가 **나에게 하는 말**로 바꿔 돌려주는 상호작용을 설계하고, 그 상호작용의 전제인 "거울의 신뢰성과 안전"을 **사람 참가자 없이** 평가하는 연구용 시스템입니다.

- **RQ1.** 자기지향 변환은 조언의 의미를 얼마나 보존하며, 사용자의 판단 여지를 줄이는 변형(원문에 없던 당위·조언 추가, 강도 강화)은 얼마나, 어떤 형태로 나타나는가?
- **RQ2.** 판정·점검 파이프라인은 부적절한 입력(조언 아님·비난·위험)과 심각한 변환 오류(반전·추가)를 얼마나 걸러내며, 걸러내지 못하거나 의도적으로 통과시킨 변형은 어떤 유형인가?

자료는 샘플 조언(연구자 작성·페르소나 생성·공개 데이터)과 오류 주입 문장이고, 판정은 연구진 코더 2명이 합니다. 참가자 화면은 **시연용**으로 남아 있습니다(논문의 시스템 설명·그림용, 연구 자료로 쓰지 않음).

## 실험 순서 (대시보드 `/admin`)

1. **실험 탭 ① 샘플 조언 세트**: 예시 불러오기, 직접 추가(연구자 작성·공개 데이터, 한 줄에 하나씩), JSON 가져오기, **페르소나 생성**(페르소나 `content/validation/personas.json` × 라벨 × n개, 생성 모델 `GEN_MODEL`). 위험 샘플은 연구자가 직접 쓰는 것을 권장합니다. 샘플마다 의도 라벨과 출처가 붙습니다.
2. **코딩 탭 '정답 라벨'**: 코더 2명이 샘플마다 정답 라벨을 판정 → 합의. 확정 전에는 의도 라벨로 계산합니다(결과 화면에 확정 개수 표시).
3. **실험 탭 ③ 실험 실행**: 샘플마다 실제 서비스와 같은 파이프라인(규칙 사전 검사 → AI 판정·변환 → 형식·의미 점검 → 실패 시 다시 변환)을 반복(1~5회) 실행합니다.
4. **실험 탭 ② 오류 주입 세트**: 실행에서 점검을 통과한 올바른 변환문에 오류를 하나씩 넣습니다(반전·내용 추가 = 막아야 함, 강도 강화·약한 일반화·표현만 바꿈 = 통과해야 함). 직접 추가도 됩니다. 그다음 다시 실행하면 주입 문장은 점검만 돌립니다.
5. **코딩 탭 '변환 오류'·'오류 주입 문장'**: 첫 변환문의 오류 유형(의미 추가·반전·왜곡·누락·강도 강화·강도 약화·과도한 일반화), 주입 문장의 오류 유형(주입 유형을 모른 채 판정 → 주입 타당도).
6. **결과 탭**: 실행을 골라 봅니다.
   - 결과 문장(원고 초안용, 복사 버튼)
   - RQ1: 의미 보존(오류 없음·미세·심각), 판단 여지를 줄이는 변형 비율과 사례, 오류 유형, 출처별
   - RQ2: 정답 라벨 × 시스템 결과 표, 부적절한 입력이 돌아가지 않은 비율, 정상 조언을 잘못 막은 비율, 막은 단계(규칙·AI 판정·점검), 걸러내지 못한 입력, 주입 유형별 막음·기대대로·주입 타당도, 놓친 심각한 오류, 자연 발생 오류 × 첫 점검, **통과시킨 변형**(사용자 화면이 받아내야 할 몫)
   - 반복 일관성, 응답 시간, 코더 일치도(일치율·κ), **실행 비교**(프롬프트·모델 버전별)
   - 내려받기: 항목별 CSV, 오류 주입 CSV, 실행 원본 JSON, 결과 보고서 HTML

생성·실행은 백그라운드로 돌고 위쪽에 진행 상황이 보입니다. 한 번에 작업 하나만 돌릴 수 있습니다. 터미널로도 같은 일을 할 수 있습니다:
```
npm run samples -- --seed                                              # 예시 불러오기
npm run samples -- --personas all --labels ok,not_advice,blame --n 3   # 페르소나 생성
npm run experiment -- --repeats 3 --note "v4 첫 실행"                    # 실행
npm run inject -- --limit 10                                           # 오류 주입 세트 (최근 실행 기준)
```

**모델 분리 권장**: 같은 모델이 조언을 만들고, 바꾸고, 점검하면 결과가 유리하게 나올 수 있습니다. `.env`에서 `GEMINI_MODEL`(변환), `CHECK_MODEL`(점검), `GEN_MODEL`(생성·주입)을 다르게 정하세요. 같으면 대시보드에 경고가 뜹니다.

모의 모드(키 없음)는 화면·경로 확인용이고 결과는 의미가 없습니다. 조언에 태그를 붙이면 경로를 시험할 수 있습니다: `#notadvice #blame #risk #badjson #error #slow`(변환), `#reversal #addition`(점검 실패), `#reversal1`(첫 점검만 실패 → 다시 변환 성공), `#you`(2인칭 남음 → 형식 실패).

## 시연용 참가자 화면

참가자 화면 위에는 3구간만 보입니다: **1. 캐릭터 돕기 → 2. 내 이야기 → 3. 마무리**. 조언이 돌아온다는 사실은 미리 알리지 않습니다(거리두기 조건). 모든 단계는 앞으로만 진행됩니다.

| 단계 | 화면 | 입력 |
|---|---|---|
| S1 시작 | 안내·동의 + 사전 선별("뭘 해도 안 될 것 같다"는 생각을 해 본 적? 없으면 종료) + 관련성 1~5 | 탭 |
| S2 고정 대화 | 캐릭터 첫 대사 → 선택지 3개(공감·구체화·탐색) 중 1개 → 고정 답 + 질문 | 탭 1회 |
| S3 조언 | 조언 1개. "조언 아님"이면 캐릭터가 한 번 더 물음(재질문 1회) | 자유 입력 |
| S4 내 경험 | 그때 든 생각 한 줄 (비슷했던 상황은 선택) — **AI로 보내지 않음** | 한 줄 |
| S5 돌아온 말 | 원문과 변환문을 나란히. 잘 담김 / 조금 다름 / 많이 다름. '고치기'를 눌러야 입력창이 열림 | 탭, 고치기 선택 |
| S6 나에게 할 말 | 위에 그때 든 생각, 아래에 변환문(S5에서 고쳤으면 고친 문장). 그대로 / 고쳐서 / 미루기 / 안 맞음 | 탭, 고쳐서면 수정 |
| S7 이유 | S6 판단별 이유 선택지 하나 (+ 일부 선택지는 한 줄). 분석 범주는 화면에 안 보임 | 탭 |
| S8 설문 | q10(주도권), q11(역문항) — 디브리핑 **전에** 받음 | 탭 2회 |
| S9 마무리 | 디브리핑(조언이 돌아온 이유, 실패 경로면 돌아오지 않은 이유) → 데이터 철회 선택 | 탭 |
| 끝 | 감사 + 상담 자원 안내(교내 상담센터·109·1577-0199) | |

- **실패 경로**: 조언 아님(재질문 후 또 조언 아님)·비난·위험·AI 오류/지연·변환 점검 두 번 실패 → S4~S8을 건너뛰고 S9로.
- **그만하기**: 어느 단계에서든 S9 마무리(디브리핑·철회 선택)로 갑니다.
- 캐릭터 표정은 기본·속상함 두 가지뿐(웃는 표정 없음).

## AI 처리 (조언 판정 → 자기지향 변환 → 변환 점검)

1. **규칙 사전 검사** (`content/safety/rules.json`): 명백한 위험·비난 표현은 AI로 보내지 않고 바로 실패 경로.
2. **판정 + 변환** (Gemini, 프롬프트 `content/prompts/transform/v4.md`): `{verdict: ok|not_advice|blame|risk, self}` JSON 하나.
3. **변환 점검**: 심각한 오류만 거르고 미세한 변화(강도·약한 일반화·어휘)는 통과시킵니다(RQ1 분석 대상).
   - 형식(규칙): 2인칭(너·네가·당신…)이 남음, 빈 출력, 지나친 길이 증가(기준은 `content/study.json`의 `check`, 짧은 조언은 예외)
   - 의미(AI, `content/prompts/check/v1.md`): 뜻 반전, 원문에 없는 조언·사실 추가 (상황절은 추가로 보지 않음)
   - 실패하면 **다시 변환 1회**, 또 실패하면 실패 경로. 점검 모델은 `.env`의 `CHECK_MODEL` — 변환과 **다른 모델 권장**.
4. AI로 보내는 것은 **S3 조언 원문과 그 변환문뿐**. S4~S7 입력은 보내지 않습니다(테스트로 확인).

## 노트북에서 실행

1. Node.js 20.12 이상 설치 (https://nodejs.org)
2. 이 폴더에서 처음 한 번: `npm install`
3. `.env.example`을 복사해 `.env`를 만들고 `GEMINI_API_KEY`를 넣습니다. 키를 비워 두면 **모의(mock) 모드**(가짜 변환 문장)로 동작합니다.
4. `npm start` → 창에 주소가 나옵니다.
   - 참가자 화면: `http://localhost:3000` (`?pid=P01`을 붙이면 참가자 ID가 채워짐)
   - 연구자 대시보드: `http://localhost:3000/admin`

자체 테스트 데이터를 따로 두려면 `.env`에 `DATA_DIR=data-selftest`를 넣고 켭니다.

## 다른 사람에게 링크로 받기 (인터넷)

1. cloudflared 설치 (한 번만) — 윈도우: `winget install --id Cloudflare.cloudflared` / 맥: `brew install cloudflared`
2. `.env`에 `ACCESS_CODE=아무코드`를 넣고 서버를 켭니다(`npm start`).
3. 새 창에서 `npm run tunnel` → 화면에 나온 **참가자 링크**를 보냅니다. 예: `https://xxxx.trycloudflare.com/?pid=P01&code=아무코드`

## 대시보드 탭

- **실험**: 샘플 세트 · 오류 주입 세트 · 실행 (위 순서)
- **결과**: RQ1·RQ2·일치도·실행 비교·내려받기
- **코딩**: 정답 라벨 / 변환 오류(실행별) / 오류 주입 문장. 코더 1·2가 따로 판정 → '합의'에서 다르게 본 것만 정함. 의도 라벨·출처·시스템 결과·주입 유형은 숨김.
- **시연 세션**: 참가자 화면을 해 본 기록 (연구 자료 아님)
- **설정·내보내기**: 현재 모델·프롬프트·점검 기준, 샘플 세트 JSON, 코딩 CSV

접근: `.env`에 `ADMIN_TOKEN`이 없으면 서버를 켠 PC에서만 열립니다.

| 무엇 | 파일 |

| 캐릭터 이름·대사·선택지·재질문·마무리 | `content/character/character.json` (초안, 이름은 임시) |
| 표정 이미지 | `content/character/faces/{neutral,sad}.svg` — `npm run faces`로 만든 단순 도형 초안. 같은 이름의 SVG로 바꿔 넣으면 됨 |

| 규칙 사전 검사 | `content/safety/rules.json` |
| 코딩 기준(오류 유형·판단 여지 축소 표시·주입 유형·정답 라벨) | `content/coding/criteria.json` |

## 테스트

```
npm test            # 파이프라인(규칙·판정·점검·다시 변환·오류/지연·전송 범위), 시연 흐름, 샘플·생성·주입·실행, RQ1·RQ2 계산, 코딩·합의·일치도, 내보내기, 접근
npm run test:e2e    # 브라우저: 시연 ok·실패 경로 완주 + 대시보드(샘플→실행→주입→재실행→결과→코딩)
```
테스트는 `tests/fixtures/content`의 [TEST] 가상 콘텐츠와 가짜 AI를 쓰므로 키가 필요 없습니다.
